## 1. Executive Summary

**AI Lead Intelligence Platform** is a SaaS platform that automates the full B2B sales pipeline: discovery, enrichment, scoring, outreach, and follow-up — acting as an AI-powered SDR for freelancers, digital agencies, and software consultancies.

**Scope**: ~50 microservices/modules organized into 10 core bounded contexts, running on Python (FastAPI) + React (Next.js), backed by PostgreSQL, Redis, Elasticsearch, and pgvector.

**Timeline**: 8 phases over ~16-20 weeks for a single full-stack developer.

### 2.2 User Flows

**Flow 1: Automated Discovery**
```
User inputs: location + radius + intent
  → Geocode location
  → AI interprets intent → generates search rules
  → Fan out to multiple sources (Google Maps, directories, etc.)
  → Deduplicate & normalize results
  → Store companies + raw data
  → Trigger enrichment pipeline
```

**Flow 2: Opportunity Scoring**
```
Enriched company data
  → Run technical analysis (SEO, performance, security)
  → Run business analysis (presence, reviews, activity)
  → Calculate Opportunity Score (0-100)
  → Generate AI analysis report
  → Prioritize & rank
```

**Flow 3: Automated Outreach**
```
Scored lead
  → AI generates personalized email, WhatsApp, LinkedIn message
  → User reviews (or auto-approve)
  → Send via configured channel
  → Track opens, clicks, replies
  → AI handles responses, schedules meetings
  → Escalate to human when needed
```

**Flow 4: SDR Agent**
```
Outbound message sent
  → Monitor for response
  → AI classifies response (interest, objection, meeting request, etc.)
  → Generate appropriate reply
  → Handle objections with trained responses
  → Schedule meeting when ready
  → Notify human (via Slack/Telegram/Dashboard)
```

## 3. Risk Analysis

### 3.1 Technical Risks

| Risk | Severity | Mitigation |
|------|----------|------------|
| LinkedIn scraping detection/blocks | **High** | Use official API where possible, public profiles only, respect ToS, rate limiting, rotate IPs |
| CAPTCHA/Cloudflare blocking | **High** | CAPTCHA solving services (2captcha), residential proxy rotation, headless fingerprint randomization |
| AI API costs spiraling | **Medium** | Model routing (cheap for simple, expensive for complex), response caching, batch processing, local models for bulk |
| Data quality/deduplication | **Medium** | Fuzzy matching (RapidFuzz), canonical company profiles, merge strategies |
| Browser resource consumption | **Medium** | Browser pool management, Chromium reuse, headed mode for debugging, resource limits |
| PostgreSQL performance at scale | **Low** | Proper indexing, partitioning by tenant, read replicas when needed |

### 3.2 Legal Risks

| Risk | Severity | Mitigation |
|------|----------|------------|
| GDPR/Privacy compliance | **High** | Consent management, data minimization, right to erasure, only process publicly available business data |
| CAN-SPAM / Anti-spam laws | **High** | Opt-out mechanisms, unsubscribe links, sending limits, domain reputation monitoring |
| LinkedIn Terms of Service | **High** | Never scrape private data, use public profiles only, respect rate limits, consider Sales Navigator API |
| Web scraping legality | **Medium** | Respect robots.txt, no circumvention of access controls, store only publicly available data |
| WhatsApp Business API compliance | **Medium** | Use official Business API, message templates, opt-in requirements |
| Data processing agreements | **Medium** | DPA with subprocessors (hosting, AI APIs), clear privacy policy |

### 3.3 Scalability Risks

| Risk | Severity | Mitigation |
|------|----------|------------|
| 1M+ companies search performance | **Medium** | Elasticsearch for full-text, PostgreSQL partitioning, materialized views for analytics |
| Real-time scraping at scale | **Medium** | Distributed job queue (Redis + worker pools), proxy rotation, browser pool sizing |
| AI inference throughput | **Low** | Async processing, queue-based architecture, model batching |

## 4. Technology Decisions

### 4.1 Backend: Python (FastAPI)

**Decision**: Python with FastAPI

**Justification**:
- **Scraping ecosystem**: Playwright for Python, BeautifulSoup, Scrapy, httpx — Python dominates web scraping
- **AI/ML ecosystem**: OpenAI Python SDK, Anthropic Python SDK, LangChain, sentence-transformers — Python is the native language of AI
- **Async support**: FastAPI is natively async (ASGI), handles WebSockets, SSE, background tasks
- **Task queues**: Celery with Redis broker — mature, battle-tested for long-running scraping/enrichment jobs
- **Type safety**: Pydantic v2 for data validation (5-50x faster than v1), SQLAlchemy 2.0 with async
- **Developer experience**: FastAPI auto-generates OpenAPI docs, dependency injection, excellent DX

### 4.2 Frontend: Next.js 14+ (App Router)

**Decision**: Next.js with TypeScript, Tailwind CSS, shadcn/ui

**Justification**:
- **SSR/SSG**: Server-side rendering for SEO-optimized pages (public-facing reports)
- **React ecosystem**: Largest ecosystem, shadcn/ui for professional components
- **TypeScript**: End-to-end type safety with auto-generated API client
- **App Router**: Server Components, streaming, parallel routes for complex dashboard layouts

### 4.3 Database Stack

| Component | Technology | Purpose |
|-----------|-----------|---------|
| Primary DB | PostgreSQL 16 | Core business data, ACID transactions |
| Vector DB | pgvector (PostgreSQL extension) | Embeddings for semantic search |
| Cache | Redis 7 | Session cache, job queues, rate limiting, pub/sub |
| Search | Elasticsearch 8 | Full-text search, analytics, aggregations |
| Object Storage | MinIO / S3 | Screenshots, PDFs, attachments |

**Decision: pgvector over dedicated vector DB**
- One less service to operate
- Sufficient for <10M embeddings (our scale)
- Can migrate to Qdrant later if needed
- Unified queries (SQL + vector in one query)

### 4.4 Task Queue & Workers

**Decision**: Celery + Redis

**Alternatives considered**:
- BullMQ (Node.js) — would require Node.js backend
- ARQ (Python, Redis) — lighter but less mature
- Dramatiq — good alternative, but Celery has larger ecosystem

**Architecture**: Celery workers grouped by queue:
- `scraping` — browser-heavy scrapers
- `enrichment` — API calls to enrichment providers
- `ai` — LLM inference jobs
- `outreach` — email/WhatsApp sending
- `default` — general tasks

### 4.5 AI Stack

| Layer | Technology |
|-------|-----------|
| LLM Gateway | LiteLLM (unified interface for all providers) |
| Embeddings | OpenAI text-embedding-3-small / local model |
| RAG | Custom pipeline (langchain-core, not full LangChain) |
| Agent framework | Custom (function calling + tool registry) |
| Memory | Redis (short-term) + PostgreSQL (long-term) |

**Decision: LiteLLM as model router**
- Single interface for OpenAI, Anthropic, Gemini, local Ollama
- Automatic fallback, rate limit handling, cost tracking
- Model aliases: `fast` → gpt-4o-mini, `smart` → gpt-4o, `creative` → claude-sonnet

### 4.6 Infrastructure

| Component | Technology |
|-----------|-----------|
| Containerization | Docker + Docker Compose (dev), Kubernetes (prod optional) |
| Reverse Proxy | Traefik (auto-SSL, service discovery) |
| CI/CD | GitHub Actions |
| Monitoring | Prometheus + Grafana |
| Logging | Structured JSON → Loki |
| Tracing | OpenTelemetry |

## 8. Module Breakdown

### Module 1: Platform Core
**Purpose**: Auth, multi-tenancy, RBAC, settings, audit
**Dependencies**: None
**Deliverables**:
- JWT authentication (access + refresh tokens)
- OAuth2 (Google, GitHub)
- Multi-tenant data isolation (row-level security)
- Role-based access control (owner, admin, member, viewer)
- Audit logging
- Organization settings

### Module 2: Scraping Engine
**Purpose**: Browser automation, proxy management, plugin system
**Dependencies**: None
**Deliverables**:
- Playwright browser pool (Chromium, reuse contexts)
- Proxy rotation (residential, datacenter)
- CAPTCHA detection + solving integration
- Rate limiting per source
- Plugin registry with auto-discovery
- Base scraper class + interface
- Anti-detection (fingerprint randomization, human-like behavior)
- robots.txt parser and compliance checker
- Job queue integration (Celery)

### Module 3: Discovery Service
**Purpose**: Orchestrate multi-source searches
**Dependencies**: Module 2 (Scraping Engine)
**Deliverables**:
- Geocoding service (Nominatim + Google)
- Radius-based search
- AI intent parser (converts natural language → search rules)
- Source orchestrator (fan-out to multiple sources)
- Result deduplication (domain + name + address fuzzy matching)
- Raw result normalization
- Search history & management

### Module 4: Enrichment Service
**Purpose**: Aggregate and enhance company data
**Dependencies**: Module 3 (Discovery)
**Deliverables**:
- Tech stack detection (Wappalyzer-like, HTTP headers, meta tags, scripts)
- SEO analysis (PageSpeed, Lighthouse, meta tags, sitemap)
- Social media presence detection
- Contact enrichment (Hunter.io, Apollo, Clearbit)
- Email verification
- Company details from public registries
- Batch enrichment pipeline
- Enrichment scoring (data completeness)

### Module 5: Scoring Service
**Purpose**: Opportunity analysis and ranking
**Dependencies**: Module 4 (Enrichment)
**Deliverables**:
- Configurable scoring rules (weight per factor)
- Technical score (SSL, speed, mobile, errors, SEO)
- Business score (reviews, activity, presence, automation)
- AI analysis report generation
- Service recommendation engine
- Estimated deal value calculation
- Batch scoring pipeline
- Historical score tracking

### Module 6: AI Gateway
**Purpose**: Unified AI interface
**Dependencies**: None
**Deliverables**:
- LiteLLM integration with model routing
- Cost tracking per tenant
- Fallback chains (provider A → provider B)
- Rate limiting per model
- Response caching (semantic dedup)
- Streaming support (SSE)
- Embedding generation & storage
- RAG pipeline for company context

### Module 7: Outreach Service
**Purpose**: Multi-channel campaign execution
**Dependencies**: Module 6 (AI), Module 5 (Scoring)
**Deliverables**:
- Campaign management (CRUD, templates)
- Email sending (SMTP, SendGrid, Amazon SES)
- WhatsApp Business API integration
- LinkedIn messaging (manual only — API limitations)
- Personalized message generation (AI)
- A/B testing for messages
- Send scheduling (business hours, delays)
- Open/click/reply tracking (webhooks, pixels)
- Unsubscribe management
- Deliverability monitoring

### Module 8: SDR Agent
**Purpose**: Autonomous conversation management
**Dependencies**: Module 6 (AI), Module 7 (Outreach)
**Deliverables**:
- Conversation state machine (new → contacted → engaged → meeting → closed)
- Intent classification (interest, objection, meeting request, not interested)
- Objection handling (predefined + AI-generated responses)
- Meeting scheduling (Calendly/Cal.com integration)
- Human escalation rules
- Response time SLA tracking
- Sentiment analysis
- Conversation memory (context across messages)

### Module 9: CRM Service
**Purpose**: Pipeline and deal management
**Dependencies**: Module 5 (Scoring), Module 8 (SDR)
**Deliverables**:
- Pipeline stages (configurable per tenant)
- Deal management (create, update, close)
- Activity timeline
- Notes and attachments
- Kanban board view
- Revenue forecasting
- Win/loss analysis

### Module 10: Analytics Service
**Purpose**: Dashboards, reports, and KPIs
**Dependencies**: All other modules
**Deliverables**:
- Dashboard overview (KPIs, charts, maps)
- Pipeline analytics
- Campaign performance
- Geographic heatmap
- Revenue projections
- ROI calculator
- Custom reports (exportable)
- Real-time updates (WebSocket)
- Scheduled report delivery (email)

```
1. Register account → Login
2. Search: "empresas con sitio web obsoleto dentro de 50km de Resistencia"

4. Enrichment adds tech stack, SEO score, contact info
5. Scoring ranks companies by opportunity (top: 92/100)
6. User reviews top 10, creates campaign
7. AI generates personalized emails for each
8. Emails sent, opens tracked
9. 3 companies reply — SDR agent handles conversation
10. 1 meeting scheduled → Deal created in CRM
11. Dashboard shows: 50 found → 10 qualified → 1 campaign → 3 replies → 1 meeting → 1 deal
12. ROI calculated: platform cost vs deal value
```
